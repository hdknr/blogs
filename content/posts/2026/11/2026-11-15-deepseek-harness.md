## はじめに

DeepSeek Harness（略称 `dsh`）は、オープンソースの AI エージェント実行基盤（エージェントランタイム）です。DeepSeek が 2026 年 8 月に MIT ライセンスで公開しました。

dsh は LLM そのものではありません。LLM を「脳」とすれば、dsh はその脳に「外骨格（作業環境）」を与えるソフトウェアです。ファイル操作・コマンド実行・Web 検索・状態管理を、LLM が安全に行えるようにします。Claude、GPT、ローカル LLM などの DeepSeek 以外のモデルでも動き、`npx` 一発で試せます。用途としては Anthropic の Claude Code などと重なる部分があります。

この記事では、dsh のアーキテクチャ・特徴・用途と、試すときの注意点をまとめます。

### 用語

| 用語 | 意味 |
|---|---|
| ハーネス（エージェントハーネス） | LLM を包み込み、道具（ツール）・実行環境・状態管理を与える層。エージェントの実力はモデルだけでなく、この層の設計にも左右される |
| エージェントランタイム | エージェントのループ（推論 → ツール呼び出し → 結果の反映）を実際に回す実行基盤 |
| Cordis | dsh の土台になっている、プラグインを組み合わせてアプリケーションを作るためのメタフレームワーク（フレームワークを組み立てるためのフレームワーク） |
| MCP | Model Context Protocol。外部サーバーが提供するツールを LLM につなぐための共通プロトコル |
| コンテキストキャッシュ | プロンプトの先頭が前回と同じとき、その部分の処理をプロバイダ側で再利用して料金や遅延を下げる仕組み |
| Trajectory | エージェントの思考ステップやツール呼び出しの履歴を時系列でたどれるビュー |

## 主な特徴とアーキテクチャ

### 「すべてがプラグイン（Everything is a Plugin）」設計

dsh は、メタフレームワーク **Cordis** を基盤にしています。Cordis は 2022 年から開発されている既存の OSS で、その設計は北京大学と DeepSeek の研究者による共著論文でも理論的に整理されています。

dsh では、モデル接続、ツール、セッション管理、サンドボックス、UI に至るまで、あらゆる機能が独立したプラグインとして扱われ、実行中に着脱・差し替えできます。

プラグインを外すと、そのプラグインが登録したもの（イベントリスナー、プロンプトの一部、ツール定義など）は自動で取り消されます。機能を足し引きしてもランタイムの状態が汚れにくい設計です。ただし、シェルコマンドの実行結果のような外部への副作用までは元に戻りません。

### モデル中立（マルチモデル対応）

名前に DeepSeek と付いていますが、使えるモデルは DeepSeek 製（V4-Pro / V4.1-Flash など）に限りません。次のようなモデルを切り替えて利用できます。

- Anthropic（Claude）
- OpenAI（GPT）
- クラウド経由: Amazon Bedrock / Google Cloud Vertex AI
- 自前サーバー: ローカル LLM などの OpenAI 互換エンドポイント

モデル接続そのものもプラグインなので、「脳」を差し替えても外骨格側の設定やツール群はそのまま使い回せます。

### 拡張性と Creator mode

**Creator mode** では、チャットでの指示からエージェントにプラグインのパッケージを作らせ、インストールさせることができます。エージェントが自分の道具を自分で増やせるわけです。インストールには承認が必要で、勝手にプラグインが入る仕組みにはなっていません。

また、MCP 互換ツールの組み込みにも対応しているため、既存の MCP サーバー資産を流用できます。

### コスト最適化と可観測性

プロンプトの先頭（静的コンテキスト）を固定し、コンテキストキャッシュのヒット率を高める設計になっています。複数ターンにわたるタスクでは毎回同じ前置きを送りますが、キャッシュに当たった部分は割安に課金されるため、API コストを抑えられます。

さらに、エージェントの思考ステップやツール呼び出しの履歴（Trajectory）を可視化して追跡できます。エージェントが「なぜその操作をしたのか」を後から確かめられるのは、デバッグや監査の面で重要です。

## 主な用途

| 分野 | 例 |
|---|---|
| コーディング・開発自動化 | リポジトリの解析、バグ修正、機能実装、テストの自律実行 |
| 日常業務・ドキュメント作成 | ローカルファイルの整理、スプレッドシートのデータ分析、文書や資料の作成 |
| リサーチ・定期タスク | Web 検索による情報収集・ファクトチェック、スケジュール指定による週次レポート作成などのバックグラウンド実行 |

コーディングエージェントとしてだけでなく、汎用の業務エージェントとして使うことも想定されています。

## 使い始め方

後述の注意点のとおり、まずは使い捨ての検証用ディレクトリで動かします。Node.js をインストールしたうえで、次のように実行するとローカル Web UI が起動します。

```bash
mkdir dsh-sandbox
cd dsh-sandbox
npx @deepseek-ai/dsh web
```

起動したら、ブラウザで `http://127.0.0.1:3080` を開きます。

このほか、macOS 向けと Windows 向けのデスクトップアプリも用意されています。

## 利用上の注意

- **開発者プレビュー（Developer preview）**: 互換性を壊す変更が入る可能性があります。業務に組み込む場合はバージョンを固定しておくのが無難です。
- **隔離環境で試す**: dsh はローカルのファイル操作やコマンド実行の権限を伴います。そのため、本番環境や機密データには直接触れさせず、使い捨ての仮想マシンやコンテナ、専用の環境で試すことが公式に推奨されています。
- **Creator mode の扱い**: エージェントがプラグインを生成・インストールできるぶん、エージェントが実行できる操作の範囲も広がります。サンドボックスと承認の設定を確認してから使いましょう。

## まとめ

- DeepSeek Harness は LLM ではなく、LLM に作業環境を与える「外骨格」としてのエージェントランタイム
- Cordis を基盤に、モデル接続から UI まで全機能をプラグインとして着脱できる
- DeepSeek 以外のモデル（Claude、GPT、ローカル LLM など）にも対応するモデル中立設計
- Creator mode、MCP 互換、コンテキストキャッシュを意識した設計、Trajectory の可視化を備える
- 開発者プレビュー段階のため、隔離環境で試すのが前提

エージェントの実力はモデルだけでなく「ハーネス」側の設計にも左右される、という認識が広がっています。dsh はその中で、モデル中立かつプラグイン指向という方向性を打ち出したツールといえます。
