## はじめに

2026 年 11 月 18 日、F5 は Web サーバー「nginx」の脆弱性 10 件を公表しました。あわせて修正版の nginx 1.30.7（stable、安定版）と 1.31.9（mainline、新機能を含む開発版）をリリースしています。翌 19 日には IPA（情報処理推進機構）も注意喚起を出しました。

このうち HTTP/2 に関する 2 件は、細工した通信によるメモリ破壊につながり、認証なしでリモートから任意のコードを実行（RCE）されるおそれがあると報じられています。IPA はこの 2 件を含む 5 件を CVSS v4.0 で 9.2（Critical）と評価しています。

この記事では、脆弱性の一覧、自分の環境が対象かの確認方法、すぐに更新できないときの暫定対策、更新後の確認方法をまとめます。

## 脆弱性の一覧

[nginx の Security Advisories](https://nginx.org/en/security_advisories.html) に載っている 10 件は次のとおりです。修正版は 1.30.7 以降（stable）と 1.31.9 以降（mainline）です。ただし CVE-2026-120993 は 1.30 系には影響せず、修正版は 1.31.9 のみです。

| CVE | 内容 | nginx.org の重要度 | IPA（CVSS v4.0） | 影響を受けるバージョン |
|---|---|---|---|---|
| CVE-2026-123007 | HTTP/2 のフロー制御におけるメモリ破壊 | major | 9.2 | 1.9.5〜1.31.8 |
| CVE-2026-123633 | HTTP/2 における解放済みメモリの使用（use-after-free） | medium | 9.2 | 1.19.7〜1.31.8 |
| CVE-2026-118899 | TLS 1.3 でリクエストボディを読み込む際の無限ループ | major | — | 1.13.0〜1.31.8 |
| CVE-2026-113425 | メールプロキシモジュールにおける use-after-free | major | 9.2 | 0.5.33〜1.31.8 |
| CVE-2026-121810 | HTTP/3 における use-after-free | medium | 9.2 | 1.25.0〜1.31.8 |
| CVE-2026-123634 | resolver のレスポンス処理中の use-after-free | medium | 9.2 | 0.6.18〜1.31.8 |
| CVE-2026-120967 | stream でクライアント証明書を検証する際の SNI バイパス | medium | — | 1.25.5〜1.31.8 |
| CVE-2026-120993 | PROXY プロトコル v2 使用時の NULL ポインタ参照 | minor | — | 1.31.4〜1.31.8 |
| CVE-2026-125283 | alias と try_files を併用した際のバッファオーバーフロー | minor | — | 0.9.6〜1.31.8 |
| CVE-2026-123640 | stream ssl_preread モジュールの検証不足 | minor | — | 1.15.2〜1.31.8 |

（IPA の列の「—」は、IPA の注意喚起の表に載っていないものです）

重要度の評価は情報源によって異なります。nginx.org で medium の 3 件も、IPA は 9.2（Critical）としています。nginx.org の重要度だけを見て後回しにしないようにしてください。

影響範囲が 0.5.33 や 0.6.18 からと非常に広いため、**1.30.7 / 1.31.9 より前の nginx はほぼすべて対象**と考えてよいでしょう。

## 影響

HTTP/2 を有効にしている環境では、細工された通信によってメモリ破壊やサービス停止が起き、最悪の場合は認証なしで任意のコードを実行されるおそれがあります。HTTPS サイトの多くは HTTP/2 を有効にしているため、公開している Web サーバーやリバースプロキシは優先して対応すべきです。

TLS 1.3 の無限ループ（CVE-2026-118899）は、サービス停止につながるおそれがあります。メールプロキシ、resolver、HTTP/3 の use-after-free は、それぞれの機能を有効にしている環境が対象です。

## 自分の環境が対象か確認する

まずは現在のバージョンと、HTTP/2 の設定状況を確認します。`nginx -T` は設定ファイルを読むために root 権限が要ることが多いので、`sudo` を付けて実行します。

```bash
# バージョンの確認
nginx -v

# 設定全体から http2 / listen の行を探す
sudo nginx -T | grep -nE 'http2|listen'
```

OS のディストリビューションが配布するパッケージは、バージョン番号が上流と違ったり、修正がバックポートされていたりします。`nginx -v` の番号だけで判断せず、各ディストリビューションのセキュリティ情報も確認してください。

## 対策 1：修正版へ更新する

最優先は修正版への更新です。

- **nginx Open Source**：1.30.7（stable）以降、または 1.31.9（mainline）以降
- **NGINX Plus**：37.3.0.1 / 37.0.8.1 以降（報道ベース。CVE ごとの修正版は F5 のアドバイザリで確認）
- **コンテナ・クラウドイメージ**：ベースイメージを更新して再ビルドし、デプロイし直す

## 対策 2：すぐに更新できない場合の暫定対策

すぐに更新できない場合は、HTTP/2 を無効にすることで CVE-2026-123007 と CVE-2026-123633 の影響を緩和できます。

`http2` ディレクティブ（nginx 1.25.1 以降）で有効にしている場合は、対象の `server` ブロックで `http2 off;` にします。

```nginx
server {
    listen 443 ssl;
    http2 off;
    # ...
}
```

`listen` のパラメータとして `http2` を書いている場合は、`listen` 行から `http2` を削除します。

```nginx
# 変更前
listen 443 ssl http2;

# 変更後
listen 443 ssl;
```

注意点は次の 3 つです。

- HTTP/2 を無効にすると、クライアントとは HTTP/1.1 で通信します。**gRPC は HTTP/2 が必須なので動かなくなります**
- 塞がるのは HTTP/2 の 2 件だけです。HTTP/3、TLS 1.3、メールプロキシ、resolver などの脆弱性には効果がありません
- あくまで更新までの数日間のつなぎです。更新したら設定を元に戻してください

## 更新後の確認：古いワーカープロセスが残っていないか

設定の reload だけでは、新しいバイナリは読み込まれません。パッケージを更新したら nginx を再起動してください。また reload 後も、古いワーカープロセスが長い接続を処理し終えるまで残ることがあります。古いプロセスが残っていると、脆弱なコードが動き続けます。

更新後は、プロセスの起動時刻が新しくなっているかを確認します（Linux（procps 版 `ps`）の場合）。

```bash
ps -o pid,lstart,cmd -C nginx
```

出力にはマスタープロセス（`nginx: master process`）とワーカー（`nginx: worker process`）の両方が出ます。再起動したなら、どちらの起動時刻も更新後の時刻になっているはずです。古い時刻のワーカーが残り続ける場合は、再起動し直すことも検討してください。

## まとめ

- 2026 年 11 月 18 日、nginx の脆弱性 10 件が公表された
- HTTP/2 の 2 件は未認証 RCE のおそれがあり、IPA は 5 件を CVSS v4.0 で 9.2（Critical）としている
- nginx Open Source は 1.30.7 / 1.31.9 以降へ、NGINX Plus は F5 の情報に従って更新する
- すぐ更新できない場合は HTTP/2 を無効化する。ただし gRPC への影響と、ほかの脆弱性は塞がれない点に注意する
- 更新後は nginx を再起動し、古いプロセスが残っていないかを確認する
