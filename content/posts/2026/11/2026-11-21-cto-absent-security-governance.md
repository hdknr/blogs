## はじめに

CTO が不在の組織では、次の 3 つの機能の境界が曖昧になりがちです。

- 技術・セキュリティの**意思決定**（本来は CTO / CISO の機能）
- 日々の**運用**（情シス）
- 有事の**統制**（CSIRT）

境界が曖昧なまま運用を続けると、判断も実行も現場の担当者に集中します。その担当者が休んだり辞めたりした時点で、体制ごと止まってしまいます。

体制はゼロから設計するよりも、国内の標準ガイドラインや立ち上げ用の資料を土台にするのが定石です。本記事では、体制設計と役割分担の指針になる**公的機関・団体の資料**と**実践的な書籍**を紹介します。最後に、それらを踏まえた現実的な役割の切り分け方として「経営層が決める・情シスが実行する・兼務 CSIRT が有事に判断と調整をする」の 3 層構造を整理します。

想定読者は、CTO や CISO を置いていない中小規模の組織で、情シスやコーポレート部門を担当している人です。

## 用語の整理

| 用語 | 意味 |
| --- | --- |
| CTO | 最高技術責任者。技術戦略とアーキテクチャの最終判断を担う |
| CISO | 最高情報セキュリティ責任者。セキュリティ方針・リスク評価・予算判断を担う |
| 外部 CISO | 社外の専門家に CISO の機能を委託する形態 |
| 情シス | 情報システム部門。アカウント、端末、SaaS、ネットワークなどの日常運用を担う |
| CSIRT | Computer Security Incident Response Team。インシデントの受付・判断・調整を担うチーム |
| トリアージ | インシデントの緊急度・影響度を判定し、対応の優先順位を決めること |
| コマンダー | CSIRT の統括役。業務停止や隔離など、有事の判断を下す |
| PoC | Point of Contact。社内外（法務・広報・外部機関など）との連絡窓口 |
| ハンドラー | インシデントの処理担当。調査や復旧作業を進める |

## セキュリティ体制づくりの指針となる公的機関と団体

### 日本シーサート協議会（NCA）

- **参照資料**：「CSIRT スタータキット」「CSIRT 人材の定義と確保」
- **ポイント**：「CSIRT スタータキット」は、これから CSIRT を立ち上げる組織向けに構築の手順をまとめた資料です。「CSIRT 人材の定義と確保」では、コマンダー、PoC、ハンドラーといった CSIRT の役割が整理されています。役割ごとに誰が担うかを決める際の土台になり、少人数組織で兼務を設計するときにも使えます。

### 独立行政法人情報処理推進機構（IPA）

- **参照資料**：「[中小企業の情報セキュリティ対策ガイドライン](https://www.ipa.go.jp/security/guide/sme/about.html)」（第 4.0 版）
- **ポイント**：「経営者編」と「実践編」に分かれています。技術トップ（CTO / CISO）が不在のとき、**経営層が負うべき責任**と**現場の担当者が実施すべきステップ**の境界線を引くのに向いています。付録には、情報セキュリティ基本方針や関連規程のサンプル、インシデント対応の手引きなども用意されています。

### 経済産業省（METI）

- **参照資料**：「サイバーセキュリティ経営ガイドライン Ver 3.0」と、IPA が発行する「[実践のためのプラクティス集](https://www.ipa.go.jp/security/economics/csm-practice.html)」
- **ポイント**：経営者が CISO などのセキュリティ担当幹部に指示すべき「重要 10 項目」が定められています。CTO 不在の場合は、この「指示」を誰に割り振るかを決める基準になります。割り振り先は、情シス責任者やコーポレート部門長などです。

### JPCERT コーディネーションセンター（JPCERT/CC）

- **参照資料**：「[CSIRT マテリアル](https://www.jpcert.or.jp/csirt_material/)」
- **ポイント**：CSIRT の構想・構築・運用の 3 フェーズに分けて資料がまとまっています。組織内 CSIRT のミッション定義や、情シス（IT 運用部門）・法務・広報との連携を文書化する際の参考になります。

## CTO 不在組織の役割分担：経営層・情シス・兼務 CSIRT の 3 層構造

上記の資料を踏まえると、CTO / CISO 不在組織での現実的な切り分け方は次の 3 層構造になります。

![CTO・CISO 不在組織の役割分担を示す図。上段の経営層が意思決定と最終責任を持ち、左下の情シスに方針を指示する。右下の兼務 CSIRT は有事に情シスへ隔離・停止を指示し、経営層へエスカレーションする。外部技術顧問は情シスの運用を月次でレビューする](/blogs/images/cto-absent-security-governance-layers.png)

### 1. 意思決定・最終責任（経営層 / コーポレート担当役員）

CTO の代わりに、次の判断を担います。

- 事業リスクをどこまで許容するかの決定
- 予算の承認
- 対外公表の最終判断

### 2. 平時の基盤運用・技術実行（情シス、外部技術顧問がレビュー）

情シスが、アカウント管理、端末・SaaS の統制、バックアップなどの日常運用を担います。

技術的なアーキテクチャやセキュリティ方針の妥当性を社内で評価できない場合は、**技術顧問や外部 CISO** に月次レビューを委託し、判断の属人化を防ぎます。

### 3. 有事のトリアージ・横断調整（CSIRT：兼務チーム）

平時は情シスや総務・法務のメンバーが兼務し、インシデントを検知したときだけ CSIRT として次の役割を担います。

- **コマンダー**：業務停止・隔離を判断する
- **PoC**：法務・広報・外部機関と連絡する
- **ハンドラー**：調査・復旧を進める。端末やアカウントへの実作業は情シスに依頼する

情シスは「CSIRT の指示を受けて、実際の端末隔離やアカウント停止を実行する部隊」と位置づけます。判断と実行が分かれるので、役割が衝突しません。

## まとめ

- CTO / CISO が不在でも、その**機能**（意思決定・運用・有事統制）は誰かに割り振る必要がある
- 体制は NCA・IPA・経済産業省・JPCERT/CC の公開資料を土台に設計するのが近道
- 「経営層が決める」「情シスが実行する」「兼務 CSIRT が有事に判断・調整する」の 3 層に分け、足りない技術判断は外部の技術顧問で補う
- 判断する人と実行する人を分けておくことが、少人数組織で現場にリスクを集中させないための鍵になる
