Meta の **Muse** と Nous Research の **Hermes Agent** は、どちらもユーザーの代わりにタスクをこなし続ける「常駐型」の AI エージェントです。ただし設計思想は正反対です。Muse は**一般ユーザー向けのマネージド型クラウドサービス**、Hermes Agent は**開発者・パワーユーザー向けのオープンソースでセルフホスト型のエージェント**です。

本記事では両者の違いを整理し、「Muse から Claude や Codex を使えるのか」という疑問に答えます。結論を先に言うと、**Muse の頭脳（基盤モデル）を Claude などに替えることはできませんが、外部の道具として作業を任せる構成なら組めます**。最後に、X で話題になっていた**両方を組み合わせる運用例**を紹介します。

## Meta Muse と Hermes Agent の比較表

| 項目 | Meta Muse | Hermes Agent（Nous Research） |
| --- | --- | --- |
| 形態 | フルマネージドのクラウドサービス | オープンソース（MIT ライセンス）、セルフホスト |
| 主な対象 | 一般ユーザー、非エンジニア | 開発者、エンジニア、パワーユーザー |
| 頭脳となるモデル | Meta のモデル（Muse Spark） | モデル非依存（ローカル LLM、OpenAI、Anthropic などを切り替え可能） |
| 動く場所 | ユーザーごとに割り当てられる Meta のクラウド VM（Muse Secure VM） | ローカル PC、自前サーバー、VPS など |
| 得意なこと | メール、旅行の予約、フォーム入力、買い物、Web リサーチ | ツール呼び出し、コーディング、自動化パイプライン、独自の拡張 |
| 強み | セットアップ不要。決済やアカウント連携が簡単 | データを手元に置ける。記憶とスキルが育つ。自由度が高い |
| 導入の手間 | 小さい（アプリやブラウザでログインするだけ） | 大きい（CLI 操作、API キーの設定、サーバーの知識が必要） |

## Meta Muse の特徴

Muse は 2026 年 9 月に Meta が公開したパーソナル AI エージェントです。

- **完全なマネージド体験**: サーバー構築や API の設定は要りません。ユーザーごとに専用のクラウド VM（Muse Secure VM）が割り当てられ、アプリを閉じていてもバックグラウンドで情報収集、旅行の手配、買い物の代行などを進めます。
- **認証情報をエージェントに見せない仕組み**: パスワードや決済手段は安全なストレージに保管され、Muse 自身からは見えないとされています。インターネットへのアクセスは Muse とは別のエージェント「Sentinel」が承認し、決済には Stripe の Link を使います。ただし、これらは Meta 自身の説明で、第三者による監査を経たものではない点には注意が必要です。
- **制約**: クラウド上のいわばブラックボックスで動くため、内部のロジックやモデルは差し替えられません。データは Meta のインフラ上で処理されます。

Muse の活用例の多さについては、以前の記事 [Meta の AI エージェント Muse は「使い方の凡例が 388 通り」](/blogs/posts/2026/11/meta-muse-use-case-inventory/) でも取り上げました。

## Hermes Agent の特徴

Hermes Agent は Nous Research が公開しているオープンソースのエージェントです。

- **モデルを選べる**: 接続先は、ローカルで動くオープンウェイトのモデルから商用 API まで自由に選べます。
- **記憶とスキルが育つ**: 複雑なタスクを終えるとスキルを自動で作り、使いながら改善していきます。記憶はホスト上に残るため、**モデルを入れ替えても記憶とスキルはそのまま**です。
- **データを手元に置ける**: 自分の PC やプライベートクラウドで動かせます。ローカルモデルと組み合わせれば、社内データや個人情報を外部に出さずに運用できます。
- **制約**: セットアップと運用は自己責任です。後述のとおり、モデルの選び方を誤ると記憶が壊れることもあります。

Hermes 向けのスキルも充実しています。GitHub スターの多い順に 15 個並べた紹介（[HermesWatcher さんの投稿](https://x.com/HermesWatcher/status/2105311718825947418)）には、開発の進め方を型にした `obra/superpowers` や、Anthropic 公式のスキル集 `anthropics/skills` などが挙がっています。

### 毎日使うユーザーのレビュー

[natsume_aurlia さんが紹介していた](https://x.com/natsume_aurlia/status/2119613948223947124)、Hermes を初日から毎日使っているユーザーのレビューでは、次の点が評価されていました。

- Hermes 側の利用上限はない（自分の API キーやローカルモデル、Nous Portal のサブスクリプションを使う）
- 平均的なセッションでは、入力トークンの 94.4% がキャッシュから読まれていた（キャッシュが効くほど API 料金と応答時間が減る）
- メモリ 2GB の仮想マシンでも安定して動いた

一方でこのレビュアーは、**性能の低いモデルを使うと、作り込んだ記憶や設定をわずか数分で壊されることがある**とも警告しています。自由度の高さには、自分でモデルを選び、壊れたら自分で直す責任が伴います。

### x_search だけを単体で使う

Hermes Agent には、xAI の Grok を通じて X を検索する `x_search` というツールがあります。[MtkN1XBt さんの X の長文記事](https://x.com/MtkN1XBt/status/2056615102120648973)によると、x_search だけが目当てなら Hermes 本体のインストールや設定は要りません。必要なのは Python とパッケージ管理ツールの uv だけです。`uvx` で Hermes の xAI OAuth 認証だけを実行すれば、内部の Python API にある `x_search_tool` を直接呼び出せます。

Hermes に「x_search を使って…」と頼む方法と比べると、Grok の回答を Hermes のモデルが解釈し直す段階が省けます。そのため速く、他のエージェントにも加工の少ないデータを渡せます。ただし記事は、得られるのは **Grok による検索結果の分析であり、検索 API ではない**こと、つまり「X API がタダになった」わけではないことも強調しています。

## Muse で Claude や Codex は使えるか

この問いは、「Muse の頭脳を Claude や Codex に替えられるか」と「Muse から外部の Claude や Codex に作業を任せられるか」の 2 つに分けると答えやすくなります。

### 頭脳（基盤モデル）としては替えられない

Hermes Agent は設定でメインのモデルを OpenAI、Anthropic、ローカル LLM などに替えられます。これに対し、Muse の推論は Meta のモデル（Muse Spark）が担っています。ユーザーがこれを Claude や GPT（Codex の基盤モデル）に切り替える設定は、公開情報の範囲では見当たりません。

### 外部の作業役としてなら組み込める

ただし、Claude や Codex に作業を任せる構成なら組めます。

- **手元のマシンに仕事を渡す**: 次の節で紹介する運用例では、常時起動の Mac を Tailscale で Muse とつなぎ、Mac 上の Claude や Codex に実作業を任せています。
- **VM 内での実行**: Muse の VM は Ubuntu Linux で、ソフトのインストールやコードの作成・コンパイルができると報じられています。ここから外部モデルの API や CLI を呼ぶ使い方も考えられますが、公式に案内された使い方ではなく、本記事でも確認していません。API キーを渡す場合は、渡し方と権限の範囲に注意が必要です。

つまり、「Claude や Codex の能力を一部の工程で使わせる」という意味であれば、Muse でも実現できます。

## 併用例: Muse を指揮官にし、Hermes Agent にタスクを管理させる

「どちらか一方を選ぶ」以外の答えもあります。[Daihuku さんの「Museに全振りしてみた」という投稿](https://x.com/Daihuku0015/status/2118347320664396269)は、両者の役割を分けて組み合わせる運用例です。

![Muse に全振りした運用例の役割分担図。ユーザーの指示を Meta のクラウド上の Muse が指揮官として受け、Hermes Agent とタスク台帳をやり取りしてプロジェクトとタスクを管理し、実作業は Tailscale で接続した常時起動の Mac 上の Claude、Codex、Pi に委譲する。知見は Obsidian で全 LLM が共有し、パスワードは 1Password で管理して LLM に渡さない](/blogs/images/meta-muse-vs-hermes-agent-division.png)

投稿者は次のように運用しているそうです。

- 日常タスクやアプリ開発は **Muse を指揮官**にする
- タスクが増えると Muse でも取りこぼしや放置が起きるため、**Hermes でプロジェクトとタスクを管理**する
- Muse 自身のトークンを節約するため、**実作業は Claude と Codex に任せる**。最近入れた Pi（AI にコードの修正やコマンドの実行を任せるコーディング用のハーネス）も安くてよいという
- Mac は常時起動しておき、**Tailscale で Muse と Mac をつなぐ**。Mac 上の操作を Muse に任せられるので、快適さが数段上がるという
- **1Password を使い、パスワードを LLM に渡さない**
- **Obsidian で「第二の脳」**を作り、すべての LLM が同じ知見を共有する
- Gmail、Instagram、X などのメッセージ対応は Muse にすべて任せる

この投稿を紹介した [tetumemo さん](https://x.com/tetumemo/status/2118867283242258904)は、「指揮官と実働と記憶の分担が、そのまま設計図になっている」と評しています。

ここから読み取れるのは、**Muse の手軽さ（窓口、メッセージ対応、決済）と、Hermes、Claude、Codex の自由度（管理、実作業）を役割で分ける**という考え方です。どちらが優れているかではなく、どこを任せるかで使い分けるわけです。

## Meta Muse と Hermes Agent、どちらを選ぶべきか

- **Meta Muse が向いているケース**: 普段使いの PC やスマホで、買い物、スケジュール調整、Web リサーチなどの雑務を、セットアップなしで任せたい場合
- **Hermes Agent が向いているケース**: 機密データを手元の環境で完結させたい場合や、任意の LLM を組み合わせて自作のツールやパイプラインに深く組み込みたい場合（主に開発者）
- **両方を併用するケース**: 窓口と日常の雑務は Muse に、タスク管理や重い実作業は Hermes、Claude、Codex に、と役割で分ける場合

マネージド型の手軽さと、セルフホスト型の自由度やデータを手元に置ける安心感は、トレードオフの関係にあります。ただ、上の実例のように両者を組み合わせれば、片方の弱点をもう片方で補うこともできます。
