## 概要

Muse は Meta が 2026 年 9 月 8 日に発表したパーソナル AI エージェント。質問に答えるチャットボットではなく、タスクやプロジェクトを「実際にこなす」ことを売りにする**一般ユーザー向けのマネージド型クラウドサービス**で、日本では 2026 年 10 月 23 日に提供が始まったと報じられている。

ブラウザを持ちフォーム入力・メール送信・買い物まで代行できるため、「何ができるか」が実質ブラウザでできること全部になり、**使い方の発見コストがユーザー側に移る**のが汎用エージェント特有の課題。

## 詳細

### 主な特徴（Meta の公式発表より）

- **長時間タスク**: アプリを閉じても作業を続け、状況が変わったときや承認が必要なとき（メール送信・購入の前など）に知らせる
- **専用のクラウド VM**: ユーザーごとの Muse Secure VM 上で動き、ブラウザでフォーム入力などを行う。VM は Ubuntu Linux で、ソフトのインストールやコードのコンパイルもできると報じられている
- **認証情報を見せない設計**: パスワードや決済手段は安全なストレージに保管され Muse からは見えないとされる。外部送信は別エージェント **Sentinel** の承認を通り、決済は Link built by Stripe の使い捨てカード番号で行う。いずれも Meta 自身の説明で、第三者監査を経たものではない
- **記憶と提案**: 一度伝えたことを覚え、頼まれる前に提案する
- **提供形態**: iOS・Android・muse.ai、WhatsApp から利用。ほとんどの用途は無料で、多く使う人向けにサブスクリプションがある
- **頭脳は差し替え不可**: 推論は Meta のモデル（Muse Spark）。Claude や GPT に切り替える設定は公開情報の範囲では見当たらない

### 「活用例 388 通り」問題と GTD での棚卸し

X では「Muse にまとめさせただけで活用例が 500 件以上、類似を統合して 388 通り、実用に至っていそうな信頼度高めが 56 件」という投稿が話題になった。この数字は GTD（Getting Things Done）の流れに重ねて読める。

| GTD のステップ | 投稿の数字 |
|---|---|
| 収集（Capture） | 500 件以上の活用例を集める |
| 見極め（Clarify） | 類似を統合して 388 通り |
| 整理（Organize） | 信頼度で 56 件に絞る |
| 実行（Engage） | 自分の次の行動に落とす（ここが本題） |

世の中の活用例を網羅するのではなく、向きを逆にして**自分の繰り返し作業の表から「任せられるもの」を逆引きする**のが実用的。表には「頻度」「所要時間」「外部送信・決済の有無」「活用例あり」「判断（任せる／承認付きで試す／自分でやる）」の列を設ける。56 件は「活用例あり」列を埋める参照先として使う。

週次レビュー（GTD の見直し）には「新しい使い方で自分の表に当てはまるものはあるか」「手戻りがあった作業はあるか」「承認待ちで止まり続けている作業はないか」を足しておけば、増え続ける活用例を追いかけずに済む。

注意点として、件数は Muse 自身による未検証の集計であり、共有ページにも「Content is user generated and unverified.」と表示される。権限は任せる作業ごとに必要最小限だけ渡す（接続先とアクセス範囲はユーザーが選び、いつでも切断できるとされる）。

### Hermes Agent との比較

常駐型エージェントという点は同じだが、設計思想は正反対。詳細は [Hermes Agent](/blogs/wiki/tools/hermes-agent/) を参照。

| 項目 | Meta Muse | Hermes Agent |
|---|---|---|
| 形態 | フルマネージドのクラウドサービス | OSS（MIT）、セルフホスト |
| 主な対象 | 一般ユーザー、非エンジニア | 開発者、パワーユーザー |
| モデル | Muse Spark 固定 | モデル非依存 |
| 動く場所 | Meta のクラウド VM | ローカル PC・自前サーバー・VPS |
| 得意なこと | メール、旅行予約、フォーム入力、買い物、Web リサーチ | ツール呼び出し、コーディング、自動化パイプライン |
| 導入の手間 | 小さい（ログインするだけ） | 大きい（CLI、API キー、サーバー知識） |

Muse から Claude や Codex を使えるかは 2 つに分けて考える。**頭脳としては替えられない**が、**外部の作業役としてなら組み込める**（手元のマシンに仕事を渡す構成など。VM 内から外部 API を呼ぶ使い方は公式案内ではない）。

### 併用例：Muse を指揮官にする

X で紹介された「Muse に全振り」の運用例では、役割を次のように分けている。

- Muse を指揮官（窓口）にし、Gmail・Instagram・X などのメッセージ対応も任せる
- タスクが増えると Muse でも取りこぼすため、Hermes Agent でプロジェクトとタスクを管理する
- Muse のトークン節約のため、実作業は Tailscale でつないだ常時起動の Mac 上の Claude・Codex・Pi に委譲する
- パスワードは 1Password で管理して LLM に渡さず、知見は Obsidian の「第二の脳」で全 LLM が共有する

「指揮官と実働と記憶の分担」で、マネージド型の手軽さとセルフホスト型の自由度を補い合う構成になっている。

### 選び方

- **Muse**: 買い物・スケジュール調整・Web リサーチなどの雑務をセットアップなしで任せたい
- **Hermes Agent**: 機密データを手元で完結させたい、任意の LLM を自作パイプラインに組み込みたい
- **併用**: 窓口と雑務は Muse、タスク管理や重い実作業は Hermes・Claude・Codex に
