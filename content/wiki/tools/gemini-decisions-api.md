## 概要

Gemini Decisions API は、Google が 2026 年 11 月 11 日に発表した判定用のエンドポイント。新モデル **Gemini Decision 1**（`gemini-decision-1`）は文章を生成せず、利用者が用意した質問への答えを**確率と確信度の数値**で返す。出力トークンは 0 で、答えは最初から型の決まった数値なので、アプリ側はその値で if 文を書くだけで済む。

[Jev](/blogs/wiki/tools/jev/) と同じ「判断だけを返すモデル」の系統で、違いはテキストだけでなく画像・音声・動画・PDF を前処理なしで入力にできる点。試用者からは「動画や音声・PDF にも対応した Gemini 版 Jev」と紹介されている。

## 詳細

### 仕組みと質問形式

1 リクエストで「共有の入力」と「質問の一覧」を渡し、モデルは候補の答えを 1 回の推論で採点する。

| 形式 | 用途 | `criteria` | 返る値 |
|---|---|---|---|
| `noul` | はい／いいえ | 任意 | はいの確率、`confidence` |
| `choice` | 2〜255 択から 1 つ | 必須（選択肢名 → 説明） | 選ばれた選択肢、全候補の確率、`confidence` |
| `score` | 順序付きの段階評価 | 必須（低い順のレベル配列） | 重み付き平均、レベルごとの確率、`confidence` |

`questions` のキーは自分で付ける名前で、モデルが読むのは `instructions` の文。`input` は Interactions API と同じ Content ブロック形式。Python では `google-genai` SDK を `api_version: "v1beta"` で使い、`client.decisions.create()` を呼ぶ。

### 仕様と料金（公表値）

| 項目 | 値 |
|---|---|
| 入力 | テキスト・画像・音声・動画・PDF、最大 256K トークン |
| 質問数 | 1 リクエスト最大 1,000 |
| レイテンシ | 150〜250 ms |
| 料金 | 入力 100 万トークンあたり 0.10 ドル、出力 0 ドル。無料枠あり |

共有入力はリクエストごとに 1 回だけ課金され、質問を増やしても加算は指示文と `criteria` の分だけ。思考トークンや OCR・文字起こしの別料金もない。Google は較正誤差（「確率 0.8」と答えた問題の約 8 割が正解か、のズレ）が最小だったとしているが、いずれも自社公表値。

試用例では、10 分の動画を 10 秒 × 60 本に切って 6 問ずつ聞いても約 9.2 万トークン（約 1.4 円）。動画の場面分割や音声の内容分析は良好だった一方、ささやき声や早口といった声の調子の聞き分けは期待ほどではなかった。

### 使うときの注意

- `noul` の確率は 0.01〜0.99 に収まるので、`> 0.99` のような条件は成立しない
- `choice` は該当なしでも必ずどれかを選ぶ。説明付きの `other` を用意する
- 選択肢のキーはアルファベット順に並べ替えて渡される（「最後に置いた」は効かない）
- 数値・日付の比較はコードで済ませ、結果をテキストとして入力に含める
- 入力は信頼できないものとして扱う。分類対象の文章の誘導で判定が揺らぎうるので、お金が動く処理の前には別のチェックを置く（[プロンプトインジェクション](/blogs/wiki/concepts/prompt-injection/)）
- コンテキストキャッシュや Batch API はないので、同じ長い文書への質問は 1 リクエストにまとめる
- 閾値はサンプルの値を流用せず、自分のデータに人手でラベルを付けて決める

### Jev との使い分けと置き場所

Jev は入力 100 万トークンあたり 0.042 ドル・70〜500 ms で、テキストだけなら価格面で有利。

| 用途 | 使うもの |
|---|---|
| テキストだけの大量の分類・判定 | Jev |
| 動画の場面分割、音声の内容分析、PDF・画像の大量仕分け | Gemini Decisions API |

Google 社内ではモデルルーティング（問い合わせの意図を分類して適切なモデルと思考レベルに振り分け、最大 40% のレイテンシ削減）や、MCP ツール向けの安全レイヤーに使われている。AI エージェントのツール選択・ポリシーチェック・上位モデルへのエスカレーションといった**制御面の部品**として置くのが向いており、文章生成や名前・日付の抽出は従来どおり生成モデルの構造化出力の出番。
