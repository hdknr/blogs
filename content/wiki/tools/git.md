## 概要

Git は、ファイルの変更履歴を記録して過去の状態に戻せるようにする**分散型のバージョン管理ソフトウェア**。コンソールで動く普通のアプリケーションで、GitHub・GitLab・Bitbucket のような「Git のリポジトリを置くクラウドサービス」とは別物である。

初学者が押さえるべき全体像は 1 点に集約できる。変更は**作業ツリー → ステージングエリア → ローカルリポジトリ → リモートリポジトリ**の 4 か所を順に通る。

## 詳細

### Subversion との違い：ローカルにもリポジトリがある

Subversion ではリポジトリはサーバーにだけあり、`commit` するとサーバーに直接記録される。Git は分散型で、ローカルにもリポジトリ（`.git` フォルダ）を持ち、コミットはまずローカルに積まれる。チームと共有されるのは `git push` してから。

ローカルに全履歴を持つため、大きなバイナリファイルを履歴に積むと `git clone` のたびに巨大なダウンロードが発生する。大きなバイナリは Git で直接管理せず、必要なら Git LFS などの拡張を使う。一度履歴に入れたファイルを後から消すのはとても面倒。

### 4 つの置き場所

| 場所 | 中身 | 主な操作 |
|------|------|----------|
| 作業ツリー | エディタで編集して保存したファイル | `git add` でステージングエリアへ |
| ステージングエリア | 次のコミットに含める変更 | `git commit` でローカルリポジトリへ |
| ローカルリポジトリ | `.git` フォルダ。コミット履歴の全量 | `git push` でリモートリポジトリへ |
| リモートリポジトリ | GitHub などに置かれた共有用の履歴 | `git pull` / `git clone` でローカルへ取り込む |

`git commit` まではネットワークを一切使わない。保存しただけではコミットできず、ステージングという「もう 1 工程」を挟むのが初学者のつまずきどころ。

### 最初に済ませる初期設定

- **名前とメールアドレス**: 未設定だとコミット時にエラーになる。`git config --global user.name` / `user.email` で設定する（リポジトリ単位なら `--local`）。GitHub に公開するリポジトリではこのアドレスが誰でも見られるので、私用アドレスを出したくなければ GitHub の noreply アドレス（`ID+ユーザー名@users.noreply.github.com`）を使う
- **初期ブランチ名**: GitHub の新規リポジトリは `main` だが、ローカルの `git init` は設定しなければ今も `master`。Git 2.56 では「Git 3.0 で `main` に変わる」というヒントが出る。`git config --global init.defaultBranch main` で揃えるとヒントも消える

### VS Code での基本操作

| 操作 | コマンド | VS Code |
|------|----------|---------|
| リポジトリ作成 | `git init` | — （隠しフォルダ `.git` がローカルリポジトリの実体） |
| 状態確認 | `git status --short`（未追跡は `??`、追加済みは `A`） | ソース管理アイコンのバッジ |
| ステージ | `git add <file>` | ファイル名右の ＋（変更をステージ） |
| コミット | `git commit -m "..."` | メッセージ欄に入力してチェックマーク。空メッセージは不可 |
| 同期 | `git pull` / `git push` | ステータスバー左下の同期ボタン |

### ブランチ・タグ・その他

- **ブランチ**: 「ブランチの上にコミットがあるのではなく、コミットの連なりそのものがブランチ」。分岐した変更を合流させるのがマージ
- **`git switch` / `git restore`**: Git 2.23（2019 年）から、ブランチ操作とファイル復元を兼ねていた `git checkout` を役割で分けた。`git switch -c <name>` で作成と移動
- **タグ**: 特定のコミットに `v1.0.0` のような名前を付ける。基本的に後から動かさない
- **リモートへの push**: サービス上でリポジトリを作り、`git remote add` で登録して `git push`。逆にサービス側を先に作って `git clone` から始める方法もある
- **`.gitignore`**: `node_modules/`・`dist/`・`*.log` など管理しないファイルを除外する
