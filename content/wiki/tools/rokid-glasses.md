## 概要

[Rokid スマートAIグラス](https://jp.rokid.com/products/rokid-glasses)（グローバル名 Rokid Glasses）は、フューチャーモデル株式会社が日本で展開するスマートグラス。2026 年 9 月時点の公式ショップ価格は 109,890 円（税込）。標準機能として翻訳・撮影・AI 検索・ナビ・文字起こしを持ち、独自アプリはアプリ基盤 **AIUI** で作る。

スマートグラスのアイデア出しは、ハードの制約を知らずにやると全部「スマホでいいのでは」に着地する。制約を先に押さえると、案の良し悪しがかなり機械的に判定できる。

## 詳細

### ハードウェア

| 項目 | 内容 |
|---|---|
| ディスプレイ | 光導波路 + Micro-LED。グリーン単色、最大 1,500 ニト |
| カメラ | ソニー IMX681（1,200 万画素）、109° 広角 |
| チップ | Qualcomm AR1 + NXP RT600 のデュアル構成 |
| バッテリー | 210mAh。外すと省電力、装着で復帰 |
| 重量 | 約 49g |
| 連携 | スマホアプリ「Hi Rokid」と Bluetooth（Android 10+ / iOS 16.0+） |

翻訳はオンラインで 89 言語以上、うち日本語・英語など 8 言語はモデルを入れればオフラインでも動く。**標準機能のリストはアイデア出しでは引き算の材料になる。**

### AIUI の開発モデル

- ブラウザ IDE「Craft」（`js.rokid.com/craft`）で書き、パッケージ化した `.aix` をスマホの Rokid アプリからグラスへ配信する。ケーブル不要
- 言語は JavaScript。画面は `<script def>` / `<script setup>` / `<page>` / `<style>` の 4 セクションを持つ単一ファイルコンポーネント `.ink`（Vue の `.vue` に近い）
- テンプレートは WeChat ミニプログラム互換（`view` / `text`、`ink:if` / `ink:for`）だが、`App({...})` / `Page({...})` ではなく **ES module の default export** で書く
- タップ・ダブルタップ・スワイプは `Enter` / `Backspace` / `ArrowUp` / `ArrowDown` のキーイベントで届く。ダブルタップはホーム操作に使われがちなので横取りしない
- 外部通信には AIUI Studio でエージェントの Network Access を ON にする

### 実機で効く制約

- **実機に `crypto` も `btoa` も無い** — ドキュメントにあるのに `crypto is not defined`。SwitchBot API の HMAC-SHA256 署名のため SHA-256・HMAC・Base64 を自前実装した。裏を返せば、**署名さえ自前で作れば中継サーバーなしでクラウド API を直接叩ける**
- **TTS（`speechSynthesis`）は途中で止められない** — `cancel()` 未サポート。音が出るのは実機のみでプレビューは無音。読み上げは「短い 1 文」一択
- **エージェント名が音声アシスタントの予約ワードと衝突する** — 「スマートホーム」「家電連携」だと起動できず、「家の確認」のような中立な名前なら起動した
- `fetch(url, undefined)` が落ちる（引数 1 個なら通る）など、**ドキュメントと実機の挙動がずれる**。プレビューで動いても実機で落ちる。配信直後だけ落ちて再起動で直ったこともある

検証は必ず実機で行い、切り分けには「動く既存アプリとコードを完全一致させて試す」が効いた。

### アプリ案を振るう 4 原則

1. **表示が数行に収まるか** — グリーン単色で視界の一部。地図・写真・表は出せない。「A-7 通路 中段」のような短い文字列に落ちるもの
2. **常時動かさずに済むか** — 210mAh で常時通信やカメラ常時認識は無理。呼ばれたときだけ動いて止まる
3. **標準機能とかぶっていないか** — 翻訳・文字起こし・AI 検索・ナビの素朴な再実装に価値はない
4. **答えを返す API が既にあるか** — グラスから直接 REST を叩けるので、叩き先の有無がそのまま実現性になる。ただし「外から叩ける形で公開されている」かが肝

### 案の評価

| 案 | 判定 | 理由 |
|---|---|---|
| 汎用の歩行ナビ | 筋が悪い | 標準機能と衝突（原則 3） |
| 屋内・業務の順路チェックリスト | 成立 | 地図をやめ「次はどこ」だけ出す。チェックポイントでスワイプ送りにすれば常時測位も不要。順路は静的データとして内蔵できる |
| 小売店の売り場検索（店員向け） | 4 原則を全部満たす | 答えは通路・棚段・在庫の 3 行、店舗固有データは AI 検索に出ない。残る変数は店舗システムに REST の口があるかだけ |
| 設備点検・ピッキング・卓別確認・結線確認など | 成立しやすい | 売り場検索と同じ骨格 |
| 常時カメラ認識・地図表示・汎用 AI 検索 | 落ちる | 原則 2・1・3 に抵触 |
| プッシュ通知型 | 未確認 | 音声起動が入口のため、バックグラウンド受信の経路を実機で確かめていない |

案の良し悪しを分けたのは AI グラスらしさではなく、「答えが 3 行に収まるか」「呼ばれたときだけ動かせるか」という散文的な条件だった。
